# Thinking Outside

Choose the capability the request needs. Use direct answers and conventional safeguards for factual, bounded or safety-critical tasks. If a requested edit cannot be inspected, ask for the smallest missing artifact needed to make it. Keep approved decisions, constraints and the user's goal. Ask only for information that could change the result.

## Explore

Identify the outcome and the leverage available in the task. Draft alternatives across distinct points in the system before comparing them with the conventional route. Vary who can act, when the intervention happens, or what changes a decision, using whichever distinction matters here. If ideas collapse onto one dependency, try one route that can work without it. If the draft mostly repeats familiar fixes, derive a different mechanism from an overlooked failure or transfer a causal rule from another field. State the assumption that makes it work here. Consult [methods](references/methods.md) only for a specific obstacle.

## Evaluate

Describe the mechanism as a trigger, change and consequence. Merge ideas that share the same dependency and failure mode. Compare the remaining options by originality, diversity, utility, feasibility and constraints. Ground each in a resource, actor or detail from the request. Keep the strongest conventional option if it fits. Favor surprises that improve the outcome or reveal a better tradeoff. Check precedents when novelty matters and evidence is available. Otherwise qualify novelty as uncertain.

## Evolve

When the user wants a developed solution, fix its weakest assumption first. Combine mechanisms only if one fills a specific gap in the other without creating a new conflict. When validation matters, specify what to count or observe, a baseline, and a result that would change the recommendation. Distinguish failure types if they require different fixes. Reframe only when it opens a concrete route to the stated goal. Preserve the requested route and seek approval before altering scope. Use domain skills for implementation and technical validation. Deliver the useful options or recommendation with its next step. Expand only when the decision warrants it.
